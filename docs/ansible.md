# Настройка машин из кода: Ansible

Terraform (`docs/terraform.md`) создаёт машину и задаёт тариф, Ansible (`infra/ansible/`) настраивает её изнутри.
Цель — сервер с нуля целиком из репозитория: `infra-terraform` (apply) → `infra-ansible` (apply) → `game-deploy`.

## Что уже в Ansible

`site.yml`, роли:
- `base` — пользователи `game`/`caddy` и папки, подкачка 1 ГБ, сетевые лимиты (sysctl), SSH только по ключу,
  файрвол (22, 80, 443 tcp/udp), журнал ≤ 500 МБ;
- `postgres` — Postgres, настройка под маленькую машину, база `massovka` с паролем, рождённым на сервере
  (`/etc/massovka/secrets.env`), копия базы раз в сутки на 14 дней;
- `tunnels` — туннели SSH: из Нидерландов в Европу и Москву (`massovka-tunnel-eu`, `massovka-tunnel`), из Европы
  в Москву (`massovka-relay`); вход `tunnel` на игровом сервере только для проброса нужных портов. Адрес Москвы
  дает инвентарь (`moscow_ip`, пусто — туннелей в Москву нет), ключ сервера бота роль читает с Нидерландов;
- `app` — `game.env` (потолок комнат по памяти и ядрам), `game-blue/green.env`, юниты `massovka-game@` и `caddy`,
  ограничение памяти, `hosts.env` (RELAY сохраняется), `caddy.sh`. Адреса — в `group_vars/{game,infra}.yml`,
  куда переезжают комнаты (`peer_host`) — считает инвентарь по DNS. Ничего не перезапускает;
- `observe` — node_exporter и отправка журнала (оба), VictoriaMetrics, VictoriaLogs, Grafana, ночные копии базы
  игры и еженедельная проверка восстановления (Нидерланды);
- `ffmpeg` — для монтажа «Фильма матча» (только игровой сервер);
- `watch` — сторож с тревогами в Telegram (Нидерланды).

Это `infra/game/setup.sh` и `observe.sh` один в один: файлы — байт в байт, поэтому сухой прогон на живых серверах
показывает `changed=0` (проверено 24.11 на massovka-eu и massovka-infra). Пока `setup.sh` делает то же самое сам —
выкладка от Ansible не зависит.

## Что осталось в setup.sh

- доставка программ (Node, Caddy, VictoriaMetrics/Logs, Grafana, node_exporter, GeoIP) — их привозит `game-deploy`
  (раньше из Москвы часть сайтов не открывалась; с Европы можно качать прямо на сервере);
- пароли и ключи: `secrets.env` (ключ токенов, ключ нагрузки), роль базы `grafana_ro`, пароль Grafana, ключ бота;
- выкладка версии (синий/зелёный, drain) — это последовательность действий, а не состояние машины, остаётся скриптом.

Следующий шаг — `game-deploy` вызывает `ansible-playbook`, а из `setup.sh` убираются куски, которые уже в ролях.
Тонкость: `setup.sh` перезапускает игру, если поменялись `/etc/massovka/*.env` (сравнивает до и после себя).
Когда их начнёт писать Ansible, сравнивать надо с отпечатком настройки, при которой запущен активный экземпляр.
Выкладка версии (синий/зелёный, drain) остаётся скриптом: это последовательность действий, а не состояние машины.

## Как пользоваться

- Сухой прогон — сам на каждом PR с правкой `infra/ansible`; итог (`PLAY RECAP`) — в Summary прогона.
- Применить — Actions › `infra-ansible` › Run workflow, `apply` = true.
- Инвентарь — `inventory.py`: адреса из Timeweb по именам серверов, ключ SSH выводится из `TWC_TOKEN`
  (как в `provision.py`). Москва (`massovka-game`) в инвентарь не входит — она доживает неделю.
