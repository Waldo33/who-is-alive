# «Кто тут живой?» / «Who’s Alive?» — план доработки до релиза

Этот файл — задание для Claude Code. Положи его в корень репозитория `Waldo33/who-is-alive` (рядом с `package.json`) и работай по нему этап за этапом. Полное ТЗ — Claude Doc «Кто тут живой? — ТЗ для разработки»; при расхождении с этим файлом прав этот файл, а ТЗ потом обновляется.

## 1. Что это за проект

Браузерная реалтайм-игра на 2–4 игроков с телефонов. Игроки прячутся в толпе из 32 одинаковых пиксельных человечков (остальные — боты), вычисляют друг друга по поведению и бьют первыми. Подключение по ссылке или QR, без регистрации. Раунд 75 с, матч до 8 очков (~5 минут).

Сейчас готова **офлайн-песочница**: один игрок и 3 ИИ-игрока на одном телефоне, все механики раунда. Она живёт на https://who-is-alive.vercel.app/sandbox и должна оставаться рабочей на всех этапах.

Художника и композитора нет: **весь арт и звук делаются кодом** (процедурные спрайты из палитры, синтез звука на Web Audio).

## 2. Стек и структура

- Монорепо pnpm 10.18.3, Node 22, TypeScript 5.9 strict.
- `apps/web` — Next.js 15 (App Router) + Phaser 3.90. Деплой на Vercel (Hobby), Root Directory = `apps/web`, каждый push в `main` деплоится в прод.
- `packages/game-core` — правила игры **без зависимостей от Phaser, DOM и сети**: арена, A*, боты, удары, звёзды, «Море волнуется», сужение, очки, награды, ИИ-игроки, журнал событий, повтор, i18n. Детерминирован: одно зерно → одинаковый результат.
- `packages/net` — интерфейс `Transport`, `LoopbackHub` (петля в памяти), zod-схемы намерений. Реализация на Supabase — этап 4.
- `packages/assets` — палитра 32 цвета (`PAL`), цвета игроков.
- `supabase/` — пусто, сюда миграции.
- `.github/workflows/ci.yml` — lint, typecheck, test, симуляция 200 раундов.

## 3. Команды

```bash
pnpm install
pnpm dev                          # http://localhost:3000, песочница на /sandbox
pnpm lint && pnpm typecheck && pnpm test
pnpm sim -- --rounds 1000         # безголовая симуляция с проверкой инвариантов
pnpm --filter web standalone      # apps/web/dist/sandbox.html
pnpm --filter web build           # прод-сборка Next.js — гонять перед каждым push
```

Дев-режим песочницы: `?dev` (панель конфига), `?dev&speed=4` (ускорение времени, в консоли доступен `window.__kto`), `?lang=en`.

## 4. Правила, которые нельзя нарушать

1. **`game-core` остаётся чистым**: никаких импортов Phaser, DOM, `window`, сети, `Math.random()` и `Date.now()` — только `Rng` с зерном и игровое время.
2. **Ни один клиент, кроме хоста, не знает, кто из сущностей живой игрок** (кроме себя). Команды ботов и игроков одного формата; в `hit` по игроку нет `attacker`. Это проверяется тестом и на сетевом стенде.
3. **Пиксели**: только целочисленный масштаб в физических пикселях (`integerZoom` в `boot.ts`), `pixelArt: true`, `roundPixels: true`, никакого сглаживания. Цвета только из `PAL`.
4. **Все тексты — в словарях** `locale/ru.ts` и `locale/en.ts` (одна структура, тип `Dict`). Строки на canvas — не длиннее 21 символа; это проверяет `test/i18n.test.ts`, новые строки добавлять туда же.
5. **Мобильный веб**: не ломать защиту от зума (`touch-action`, поля ввода ≥ 16px, гашение двойного тапа и щипка в `shell.ts`), разблокировку звука по `touchend`/`click` (iOS), безопасные зоны.
6. Phaser импортируется как `import * as Phaser from 'phaser'` (иначе падает прод-сборка Next.js).
7. Каждый этап заканчивается: зелёный CI, `next build` проходит, деплой на Vercel, ручная проверка на телефоне. Песочница работает.
8. Коммиты маленькие и осмысленные; секреты — только в переменных окружения Vercel/Supabase, не в репозитории.

## 5. Этапы

Строго по порядку. В каждом — задачи и критерии приёмки.

### Этап A. Подготовка к сети (без видимых изменений)

Проблема: `scene.ts` читает `MatchSim` напрямую (`sim.pr`, `sim.scores`, `sim.summary`, `playerRound(...)`). У гостя в сетевой игре симуляции нет.

Задачи:
- Ввести в `game-core` тип `ClientView` — всё, что нужно экрану: фаза и её таймер, `World` (воспроизводимый из событий), своя `eid`, свои удары/звёзды/оглушение/автопилот/живость, обезличенные звёзды других, счёт по игрокам, `crowd`-ответ, итоги раунда и матча (появляются только после разоблачения).
- Интерфейс `ClientSession` с методами `intent(...)`, `tick(dt)`, событиями `onWorldEvent`, `onNotice`. Реализация `LocalSession` оборачивает `MatchSim` + ИИ-агентов (песочница).
- Сцена работает только через `ClientSession`/`ClientView`.
- Разбить `scene.ts` на модули: `render/world.ts`, `render/hud.ts`, `render/overlays.ts`, `input.ts`, `fx.ts`.
- Тест: из `ClientView` гостя нельзя получить `eid` чужих игроков до фазы `reveal`.

Приёмка: песочница внешне не изменилась; все тесты и симуляция зелёные; `scene` не импортирует `MatchSim`.

### Этап B. Лобби (этап 3 ТЗ)

Предусловие: проект Supabase создан (бесплатный план), анонимный вход включён, переменные `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, `CRON_SECRET` заданы в Vercel. Если чего-то нет — остановиться и попросить владельца.

Задачи:
- Миграции в `supabase/migrations/`:
  - `rooms(code text pk, host_id uuid, status text check in ('lobby','playing'), settings jsonb, created_at, last_active_at)`;
  - `room_members(room_code fk on delete cascade, user_id uuid, name text, color int, joined_at, pk(room_code,user_id))`;
  - `analytics_events(id, created_at, user_id, room_code, name, props jsonb)`.
- RPC (`security definer`, `set search_path = ''`): `create_room(settings) → code`, `join_room(code, name) → member` (≤ 4 участников, только `lobby`, свободный цвет 0–3), `leave_room(code)` (передача хоста следующему по `joined_at`), `claim_host(code)`, `touch_room(code)`, `set_room_status(code, status)` (только хост). Код комнаты — 4 буквы без похожих символов (без O/0, I/1, L).
- RLS: прямые insert/update клиентам запрещены; select `rooms`/`room_members` — только участникам; `analytics_events` — insert любому авторизованному, select запрещён.
- RLS на `realtime.messages` для приватных каналов (`realtime.topic()`): `room:{CODE}` — select участникам, insert хосту; `room:{CODE}:host` — select хосту, insert участникам; `room:{CODE}:p:{uid}` — select только `auth.uid() = uid`, insert хосту.
- После миграций прогнать Supabase advisors (security и performance) и исправить замечания.
- Фронт: главная → «Создать игру» → `/r/ABCD`; вход по ссылке сразу в лобби; QR на пол-экрана (пакет `qrcode`); «Позвать друзей» через `navigator.share`, иначе копирование; список игроков через Presence; имя (генерируется, меняется тапом), цвет; кнопка «Готов» (разблокирует звук и Wake Lock); настройки хоста (длина раунда 60/75/90, число раундов, детский режим); «Комната заполнена» для пятого; «Идёт игра» для опоздавших; `playerId` в `localStorage` по коду комнаты.
- `app/api/cron/cleanup/route.ts` + Vercel Cron раз в 10 минут (`vercel.json`): удаление комнат с `last_active_at` старше 30 минут, защита `CRON_SECRET`.
- Все тексты лобби — в словарях, оба языка.

Приёмка: 4 телефона в одной комнате меньше чем за 60 с от отправки ссылки; пятый видит «Комната заполнена»; перезагрузка возвращает в ту же комнату; advisors без критичных замечаний.

### Этап C. Сеть (этап 4 ТЗ)

Задачи:
- `packages/net/src/supabase.ts` — `SupabaseTransport implements Transport` на Broadcast + Presence, три приватных канала из этапа B.
- Протокол (zod-схемы, короткие ключи, целые координаты): хост → все `match_start`, `round_start`, `cmds` (пакет каждые 200 мс: `move` с путём в клетках сетки, `stop`, `face`, `act`), `snap` (позиции всех каждые 2 с), `crowd`, `star`, `hit`, `zone`, `phase`, `reveal`, `match_end`; игрок → хост — намерения из `IntentMsg`, `time_ping`, `resync`. Хост валидирует каждое входящее сообщение.
- `HostSession` (симуляция 20 Гц на телефоне хоста + рассылка) и `RemoteSession` (гость: только события → `World`), обе реализуют `ClientSession` из этапа A.
- Синхронизация часов: 5 пингов при входе, берётся минимальная задержка, повтор каждые 10 с. Задержка отрисовки 100 мс; хост назначает команды на `at = сейчас + 100 мс`.
- Своё движение без задержки: локальный расчёт пути, мягкая коррекция по подтверждению.
- Переподключение: `resync` → полный снимок раунда в личный канал. `visibilitychange` → помечать отсутствие, по возврату `resync`.
- Смена хоста: хост пропал из Presence > 5 с → следующий по порядку входа вызывает `claim_host`; текущий раунд перезапускается, счёт матча сохраняется. Экран «Хост переподключается…».
- Сетевой стенд: Playwright, 4 клиента на `LoopbackHub` с искусственной задержкой 250 ± 50 мс и потерями; тест «по трафику бота не отличить от игрока».
- Учитывать лимит Supabase Free: ~100 сообщений/с на проект; держать комнату ≤ 35 сообщений/с, при необходимости частота `cmds` снижается до 4 Гц.

Приёмка: расхождение позиций ≤ 1 пикс. после `snap` при задержке 250 мс; перезагрузка возвращает в матч; смена хоста работает; стенд зелёный в CI.

### Этап D. Полный матч по сети (этап 5 ТЗ)

Задачи: все фазы (отсчёт, игра, стоп-кадр «Море волнуется», сужение, обвинение, разоблачение с повтором из журнала, итоги, награды, конец матча, реванш, призраки) поверх `RemoteSession`. Повтор разоблачения строится из журнала событий, присланного хостом. Итоги раунда и сопоставление игрок → `eid` приходят только в `reveal`.

Приёмка: компания из 4 человек проходит матч без зависаний и рассинхрона, включая реванш.

### Этап E. Вирусные фичи (этап 6 ТЗ)

Задачи:
- OG-превью ссылки комнаты через `@vercel/og` (Edge): «{Имя} зовёт тебя в „Кто тут живой?“», пиксельный стиль, оба языка.
- Клип «Лучший момент»: окно 6 с с максимальной эвристикой (выбивание +5, выбивание в последние 3 с +3, удар по боту +2, два живых ближе 20 пикс. +1/с, третья звезда +4); видео 1080×1920, 10–12 с: момент без подсветки → тот же момент с подсветкой и именами → заставка с адресом. Рендер повтора на offscreen canvas ×6, `MediaRecorder` + `canvas.captureStream`, mp4 если поддерживается, иначе webm; индикатор «Монтируем клип…»; `navigator.share({ files })`, иначе скачивание. Можно делать раньше — в песочнице всё для этого есть.
- Карточка результата 1080×1350 PNG (победитель, счёт, 2 награды, адрес) и текстовый результат на двух языках.

Приёмка: клип отправляется в Telegram с iPhone и Android; превью показывает имя пригласившего.

Приёмка: все анимации из таблицы на месте; ни одного размытого пикселя; звук работает на iOS после первого тапа.
